# BMTC Live – Bengaluru Bus Tracking Website

A Flask web prototype that proxies BMTC route, stop, vehicle, live-location and fare endpoints documented by the community. The browser never calls the upstream service directly.

## Critical production limitations

1. The BMTC API details used here are community-maintained reverse-engineered documentation, not a published service-level agreement or permission to build a commercial/public service. Endpoints can change, block requests, return incomplete data or stop working.
2. Do not poll aggressively. This sample refreshes only when the user searches/selects a route; add caching, rate limits and obtain written approval before production use.
3. The QR code generated by this app is explicitly a **DEMO RECEIPT**, not a BMTC ticket. No payment is taken and no valid ticket is issued.
4. Before public launch, obtain written BMTC approval, an authorized ticket-validation/issuance API and payment-provider approval. Never imitate the official app's ticket QR or claim a demo receipt is accepted on a bus.
5. The ETA is only the ETA returned by the upstream BMTC endpoint. If no ETA is supplied, the app must show unavailable rather than invent one.

## Requirements

- Python 3.10+
- Internet connection
- VS Code (recommended)

## Windows setup

Open PowerShell in this folder:

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python app.py
```

Open `http://127.0.0.1:5000`.

If PowerShell blocks activation, run this once for the current terminal:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

## macOS / Linux setup

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
cp .env.example .env
python app.py
```

Open `http://127.0.0.1:5000`.

## Features included

- Search route numbers using `SearchRoute_v2`
- Search bus stops using `FindNearByBusStop_v2`
- Load route stops and currently reported vehicles using `SearchByRouteDetails_v4`
- Search a vehicle registration number using `ListVehicles`
- Track a vehicle using `VehicleTripDetails_v2`
- Request fare quotes using `GetFareRoutes` and `GetMobileFareData_v2`
- Create a clearly marked local demo receipt with a QR code
- SQLite storage for demo receipts

## Test the backend

```bash
curl http://127.0.0.1:5000/api/health
curl "http://127.0.0.1:5000/api/routes?q=335"
curl "http://127.0.0.1:5000/api/stops?q=Majestic"
```

On Windows PowerShell, use `Invoke-RestMethod` if `curl` is aliased:

```powershell
Invoke-RestMethod "http://127.0.0.1:5000/api/routes?q=335"
```

## Production checklist

- Obtain written BMTC permission and official API documentation/credentials.
- Confirm allowed polling rate, caching, data attribution and redistribution rules.
- Add user accounts, password hashing, CSRF protection, secure sessions and privacy policy.
- Use PostgreSQL/MySQL instead of local SQLite for a multi-user deployment.
- Add HTTPS, production WSGI server, reverse proxy, monitoring and backups.
- Integrate a payment gateway in test mode first, then obtain BMTC's authorized ticket-issuance/validation integration. Payment success alone does not make a ticket valid.
- Have BMTC confirm the QR payload, signing, ticket lifecycle, refunds, cancellations and conductor validation process.
- Add proper ETA confidence/staleness indicators and do not label stale GPS as live.
